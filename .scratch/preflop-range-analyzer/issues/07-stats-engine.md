## Comments

**2026-10-01 — реализовано (TDD).** 217 тестов зелёные; формула дисперсии (wᵢ²) и монотонизация BH проверены мутациями.

- `core/stats/engine.py` (без numpy в рантайме):
  - `poisson_binomial_test(p, did, w=None) → DeviationTest(n, expected, variance, observed, z)`. Проверяется одно бинарное событие; узел с fold/call/raise прогоняется по каждому действию отдельно. При `Var = 0` и расхождении `z = ±∞` (гарантированное отклонение).
  - `two_sided_p(z)`, `bh_adjust(pvalues)` — совпадает с `statsmodels.multipletests(method="fdr_bh")`, включая связи, 0 и 1.
  - `zone_of(p)`: `pure` при p > 0.9, `never` при p < 0.1, иначе `mix`.
  - `hand_group(hand)`: `pair`, `suited_broadway`, `suited_ace`, `suited_connector` (зазор ≤ 1: 98s, 97s), `suited_other`, `offsuit_broadway`, `offsuit_ace`, `offsuit_other`.
  - `analyze_node(observations, config) → list[NodeStatRow]` — верхний уровень + зоны + группы; `is_leak` = `n ≥ min_sample` и `|z| > z_threshold`; `unknown_stage_share`.
- `StatsConfig(z_threshold=2.0, min_sample=30, pure_threshold=0.9, never_threshold=0.1)` — параметры, не константы; загрузка из файла конфига — в тикете 09.
- Тесты на «игру по GTO»: точное совпадение даёт z = 0; на симуляциях |z| < 3, а по 400 прогонам z ≈ N(0, 1).

BH применяется к набору p-значений целиком; к каким строкам (только верхний уровень узлов прогона) — решает прогон анализа, тикет 09.

**2026-10-01 — ε для частот.** `StatsConfig.p_epsilon = 1e-4`: частоты ограничиваются [ε, 1−ε] при расчёте z (зоны — по исходным частотам), бесконечностей больше нет. `eps=0` возвращает точное поведение.

⚠️ Ограничение, найденное тестом `test_single_misclick_in_never_zone`: один мисклик в 500 раздачах с GTO-частотой 0 даёт z ≈ 4.25 — это всё ещё «утечка». Нормальное приближение неверно при малом ожидаемом числе событий (E = 0.05): точная вероятность хотя бы одного события ≈ 0.05, а не 2·10⁻⁵, как следует из z. Варианты исправления — в отдельном решении (точный хвост Пуассона–Бернулли при малом E или порог минимального ожидаемого числа событий).
