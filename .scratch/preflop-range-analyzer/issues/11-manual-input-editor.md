## Что сделать
- Адаптер ручного ввода + HTMX-форма: позиции, стеки, анте, действия с сайзингами, карты героя, стадия (обязательна).
- Сериализованная форма ввода сохраняется как сырьё в `hands.raw_text`.

## Критерии приёмки
- Без стадии форма не сохраняется.
- Раздача из редактора даёт ту же внутреннюю модель, что эквивалентная HH PokerStars.

## Comments

**2026-10-01 — реализовано (TDD).** 443 теста зелёные; обязательность стадии проверена мутацией.

- `core/adapters/manual.py`: `parse_manual_text(text)` (JSON или YAML) / `parse_manual(data)` → `ParsedHand`.
  - Формат: `id`, `tournament`, `level` (необязательные), `blinds {sb, bb}`, `ante {type: none|each|bb, amount}`, `button`, `seats [{seat, player, stack}]`, `hero`, `cards`, `actions [{player, action, to}]`, **`stage` — обязательно**. Суммы в фишках.
  - Все ошибки ввода выдаются разом (`ManualHandError.errors`), затем раздача проверяется нормализацией (например, рейз больше стека).
  - `stage_source = "manual"`; сырьё — канонический JSON (сортированные ключи), из него раздача восстанавливается заново.
- **Эквивалентность:** `tests/adapters/fixtures/rfi_each_ante.json` и `threebet_jam_bb_ante.yaml` дают ту же модель `Hand`, что HH PokerStars (кроме стадии) — включая ник с пробелами, игрока sitting out, BB-ante, пустое место и олл-ин.
- `STAGES` / `STAGE_SOURCES` перенесены в `core/model` (адаптер не зависит от слоя БД); `core/db/models` импортирует их оттуда.
- Веб: `POST /manual` (поле `hand`) — синхронно, без фоновой задачи (одна раздача): 201 — сохранено (номер, число решений, стадия); 400 — список ошибок; 409 — раздача с таким `id` уже есть; раздачи без `id` не дедуплицируются. На главной — редактор (textarea) с рабочим примером; тест проверяет, что пример сохраняется.

Для MVP — сырой JSON-редактор; пошаговая форма (позиции → действия) — отдельной задачей при необходимости.
