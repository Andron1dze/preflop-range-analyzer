## Что сделать
- Внутренняя модель раздачи по образцу PHH: места, позиции 8-max, стеки, блайнды, анте (включая BB-ante), карты героя, префлоп-действия.

## Критерии приёмки
- Тесты на точные значения: открытие 2.2bb с BB-ante, 3-бет в долях пота, эффективный стек при разных стеках.

## Comments

**2026-10-01 — реализовано (TDD).** 73 теста зелёные. Тесты нормализации проверены мутациями (подмена формулы доли пота и отказ от вычета анте ловятся).

- `core/model/`: `Hand`, `Seat`, `Action`, `ActionKind` (fold/check/call/raise), `AnteType` (none/each/bb); `assign_positions` — 8-max, при неполном столе выпадают ранние позиции, хедз-ап: баттон = SB, баттон на пустом месте → ошибка.
- `core/normalize/hand_class.py`: `hand_class()`, `ALL_HAND_CLASSES` (169).
- `core/normalize/preflop.py`: `normalize(hand) → list[DecisionPoint]` — для каждого действия любого игрока.
- `core/db/persist.py`: `save_hand()` — `hands` + `decisions`; герой пишется как `actor="hero"`, соперники по имени без карт; `hands.ante` хранится в bb.

**Соглашения нормализации** (их же должна использовать сетка узлов, тикет 15):
- `size_bb` — итоговая ставка после действия (raise *to* / сумма колла).
- `size_pot` — только для рейза, как у солверов: (to − текущая ставка) / (пот после колла); 1.0 = пот-сайз рейз.
- `eff_stack_bb` — min(свой стек, наибольший стек среди не сбросивших соперников); стеки на начало раздачи минус уплаченное анте, блайнды остаются в стеке.
- `line` — предыдущие действия: `POS:F|X|C|R<size_bb>[ai]` через запятую.

Не сделано (вне тикета): мёртвый баттон, хедз-ап-специфика сверх позиций, минимальный размер рейза не проверяется (короткие олл-ины допустимы).
